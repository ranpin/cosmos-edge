CR2-8B INT4 · 离线批量场景挖掘

Cosmos-Reason2-8B（INT4 AWQ 量化）部署在 Jetson AGX Orin，对真实驾驶视频做事件级离线挖掘： 一次批作业读入多段 clip，逐段输出结构化场景/事件标签，并实测吞吐与能耗。全部为真实 Orin 推理输出（非模拟）。 这是「0.1–2 Hz 事件级用例」定位的落地演示——不追求控制环帧率，追求离线处理吞吐与每段成本。

一、演示：一次批作业挖掘 8 段驾驶视频

输入 = 8 段 clip × 6 帧（前视宽角、长边 448、均匀采样）；输出 = 每段一个结构化 JSON 标签 （场景 / 光照 / 天气 / 安全相关事件 / 一句话摘要）。批作业在 Orin 上单次完成，下方数字全部来自本次真实运行。

标签口径（诚实声明）
下方标签是模型输出——这些公开 clip 没有人工标注真值，此处展示的是功能的真实运作； 事件检测的带标注可靠性证据见第二节（n=184 OOD 基准分簇正确率）。

二、评测结果

数据集（带标注证据）：nvidia/PhysicalAI-Autonomous-Vehicles 的 OOD reasoning 基准 （gated，本页不展示其帧）——184 段驾驶 clip × 6 帧 @448，8 选 1 单选，8 个事件簇 × 23 题/簇，随机基线 12.5%。 每簇正确率 = 该事件类型的检测可靠性；三精度同帧同题同标答，唯一变量 = 模型精度。 本节数字来自 cr2/eval/accuracy/driving/RESULTS.json（已入库实测）。

表 1　按事件簇的正确率（n=184，8 选 1，随机基线 12.5%）。WORK_ZONES（施工区/临时交通管制）最强 （INT4 82.6%），CYCLISTS（骑行者/微出行复杂场景）最弱（INT4 34.8%）——挖掘系统对高频显性事件可靠， 对长尾弱势道路使用者事件需人工复核。INT4 总体 50.5% vs FP16 51.6%（−1.1 pts，McNemar p=0.815 不显著）。

表 2　本次批作业（第一节 8 clip 运行）的吞吐与能耗。功率口径 = tegrastats 三轨之和 （VDD_GPU_SOC + VDD_CPU_CV + VIN_SYS_5V0），采样窗口 = 纯处理阶段（首请求开始后启动、进程退出即停，不含引擎加载）。 J/clip = P̄ × wall ÷ nclip = 50.1 W × 20.2 s ÷ 8；clips/hour = 3600 ÷ E2E 均值，为连续运行的外推值。 引擎 = backbone INT4 AWQ + lm_head INT4（最终部署形态）；表 1 的 INT4 臂为 backbone-INT4 / lm_head-fp16 引擎，两者口径差异已如实标注。

三、核心方法

输入 → 输出：每段 clip 输入 6 帧前视图像（长边 448、视频内均匀采样）+ 一条挖掘指令 （约定输出 JSON 的键与取值域）；输出一个结构化 JSON：{scene, lighting, weather, events[], summary}， 事件词表与 n=184 基准的 8 个事件簇同源（work_zone / complex_intersection / dense_pedestrians / emergency_incident / animals / special_vehicle / cyclists / road_debris）。

图 1　离线批量挖掘管线：帧序列经 ViT 视觉编码器（fp16，每帧 112 token）进入 INT4 量化的 8B backbone，贪心解码（temp=0, top_k=1, ≤300 token）产出 JSON 文本，解析为结构化标签； tegrastats 三轨功率全程采集得到每段能耗。

  • 量化部署：INT4 AWQ（backbone）+ lm_head INT4，TensorRT-Edge-LLM 引擎，Orin 32GB MAXN。 量化方法与全部口径见 CR2 篇报告（量化几乎免费：n=184 驾驶域 INT4 −1.1 pts 不显著）。
  • 批处理约束（如实披露）：视觉引擎单次预处理的 token 上限（maxHW=4096）限制并发批量—— 6 帧/请求下 batch_size=4 会超限（cuSeqlens 4480 > 4096），故本次作业 batch_size=1 顺序处理 8 请求； 离线场景关心吞吐（clips/hour）而非单请求延迟，该约束不影响用例成立。
  • 复现：输入构造 cr2/eval/mining/build_input.py、运行 cr2/scripts/orin/run_pareto.sh、 解析 cr2/eval/mining/parse_mining.py；原始输出与功率日志均已入库。
诚实边界
演示 clip 取自 dgural 公开样本数据集（README 明示不适合 benchmarking/统计分析），数字仅展示功能运作； 带标注的事件检测可靠性以第二节 n=184 基准为准。模型标签不等同人工标注，长尾事件（表 1 弱簇）用于生产须人工复核。
